# ADR-0041: Remove nominative demo identities and static passwords from Git

- **Status:** Implemented
- **Target:** v0
- **Date:** 2026-08-05
- **Decision owners:** Zuno Demo architecture team

## Context

`gitops/charts/keycloak/files/realm-zuno.json` currently contains named demo users and a shared hard-coded demo password. `evaluations/tekos/run_scenarios.py` also hard-codes the same password. The repository is public and the project explicitly requires avoiding nominative and sensitive information in Git.

## Decision

Replace named fixture identities with anonymous synthetic personas such as `consultant-user-01` and `sales-user-01`. Do not store passwords, client secrets or provider credentials in Git. Test credentials must be injected from Vault/External Secrets or CI secret stores through environment variables.

## Consequences

Public repository contents remain safe to share and test environments become reproducible without publishing credentials.

## Security considerations

Add secret scanning and repository policy checks. Treat any previously committed real credential as compromised and rotate it even if later removed from history.

## Operational considerations

Update Keycloak fixtures, evaluation harness and documentation, then add a CI rule that rejects known secret patterns and non-approved personal fixture data.

## Implementation state

**Implemented (2026-08-05).**

- `gitops/charts/keycloak/files/realm-zuno.json`'s 11 named users (`majdouline`, `fabrice`, `chris`, `adil`, `maz`, `samantha`, `paolo`, `cecile`, `jean`, `max`, `raoul`) are replaced by 13 anonymous synthetic personas: `sales-user-0{1,2}`, `consultant-user-0{1,2,3}`, `adv-user-0{1,2}`, `finance-user-0{1,2}`, `board-user-0{1,2}` (the extra two beyond the original 11 are ADR-0040's entitlement/business-role negative-test fixtures, `tekos-entitlement-only-user-01` and `consultant-role-only-user-01`). No username, email or job-title attribute identifies a real person.
- The shared literal password `ZunoDemo!2026` is removed from both `realm-zuno.json` and `evaluations/tekos/run_scenarios.py`. Every fixture user's credential is now `${vault.demo_personas_password}`, resolved at runtime through Keycloak's vault SPI (the same mechanism already used for the Google IdP secret and the `tekos-frontend` client secret). The value is generated by `ansible/roles/vault/tasks/install.yml` (`zuno/keycloak/demo-personas`) and reaches the Keycloak pod via a new `ExternalSecret` (`gitops/charts/keycloak/templates/externalsecret-demo-personas.yaml`) and `KC_VAULT_DEMO_PERSONAS_PASSWORD` env var. `run_scenarios.py` now reads it from the `DEMO_PERSONA_PASSWORD` environment variable, the same pattern already used for `TEKOS_FRONTEND_CLIENT_SECRET`.
- Client secrets and provider credentials were already vault-templated before this ADR (ADR-0024) and required no change. CI secret-scanning is out of scope here - no `.github/workflows/` existed yet at the time - and was left for ADR-0051's CI/supply-chain work.
