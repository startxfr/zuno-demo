# v0.1 – v0.3 implementation roadmap

**Purpose:** drive every open ADR in the v0.1, v0.2 and v0.3 streams to
`Implemented`. The work is decomposed into work packages (WPs), each with a
self-contained brief under [work-packages/](work-packages/) written so a
lower-capability model can execute it as a standalone task.

[docs/adr/README.md](../adr/README.md) is the **sole authority for ADR
status**. This roadmap tracks WP state only — never copy ADR status strings
here (`platform/docs/check_docs.py` validates the index/body pair; a third
copy would drift unvalidated).

## Execution model

- **1 WP = 1 brief = 1 reviewable change-set** (large WPs split into
  lettered parts, each independently committable).
- Every brief separates **repo changes** (model-executable, verifiable from
  the repository) from **operator/human steps** (cluster, credentials, GPU,
  external services). Repo work merging moves the ADR to
  `Partially implemented` with the residual operator actions enumerated in
  the ADR body (the ADR-0115 gap-list pattern); the listed operator
  confirmations then move it to `Implemented`. ADRs with no operator
  dependency go straight to `Implemented` on merge.
- Stub ADRs are **promoted to full ADR files first** (Step 0 of their
  brief), following the repository's promotion convention: the roadmap
  container keeps the `### ADR-0NNN` heading (and any explicit anchors),
  its body becomes a pointer line, the index row flips to a direct link,
  numbers are retained.
- **WP state machine:** `Not started → Repo work in review → Repo work
  merged → Operator pending → Done`. `Done` requires the brief's
  Status-updates section to have been executed (ADR body + index + tracker +
  brief + MEMORY.md) and `python3 platform/docs/check_docs.py` to pass.
- **Immutability boundary:** only ADR `**Status:**` lines, dated
  gap/progress lists, and stub-body promotion pointers are editable.
  A change of direction requires a superseding ADR, never an edit.
- **Standing rules for every WP:** never touch the uncommitted ADR-0344
  change set if still present; new Dockerfiles enter
  `.github/workflows/build-publish.yml`'s matrix; new Makefile components
  need matching `ansible/roles/<name>[_build]`; new charts pass
  `platform/security/check_workload_hardening.py`; WP-04 stage 3 (which
  would have made `check_no_latest_tags.py` blocking) is deferred
  (2026-08-22, ADR-0115 closed) — charts keep `tag: latest` until a future
  ADR reactivates that stream; Makefile verbs are the source of
  truth (`d0: check install uninstall reconcile all`;
  `d1: check install build uninstall all`).
