- **Token ceiling (R-543).** Proven on kind with a mock LLM, not on demo333 (UnifAI e2e-kind run 42579374070, commit `1a31a81a3`): with
  `spec.ceilings.maxTokensPerTurn: 2000` and a mock reporting 2500 tokens per call, the turn is cut at the second call with "Token ceiling
  reached for this turn (2500/2000 tokens)". The per-agent key `zuno.limits.max_tokens_per_turn` is proven by composition, not by one end-to-end run: the operator reads it (agent and task, the task wins), the controller test renders it into the node config (`agentbundle_test.go`, 40000 on the agent, 20000 on a task), and the worker cut above runs on that same node config field. No run uses the key alone with a real artifact. Nothing is
  enforced until a bundle sets it.
- **Token ceiling (R-543), proven on demo333 (2026-11-11).** A throwaway bundle with `spec.ceilings.maxTokensPerTurn: 300`, played in the UnifAI UI as `ai-ops-01`, ended a turn with one tool call on "Token ceiling reached for this turn (1893/300 tokens)". Two facts the first attempts exposed: the ceiling is checked before each model call, so a turn with a single model call is never cut (a 30-line answer passed untouched); and the ai-gateway did not send the usage of a streamed call, so nothing was counted until `20954f04` (it republishes the usage when the caller sets `stream_options.include_usage`; Build `ai-gateway-53`). The per-turn event log (one `agent_error`, session still usable) was not read: the evidence is the UI screenshot.
- **RHACM source private (`d49b5d6e`, 2026-11-09).** `stolostron/rhacm-docs` has no LICENSE file, so `rhacm-2-17-docs` is `visibility: private`
  until that is clarified. The switch did not re-ingest (1056 pages kept). A non-owner persona gets no RHACM result; the same queries were not
  measured before the switch, so this is consistent with enforcement, not a before/after proof.
