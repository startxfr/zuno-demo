## Limits of the sprint

- **Marker images are not enough for a chat answer.** An answer grows while the model writes, and the marker images show
  only the instants of the markers. Lesson from the `lightspeed` take above: scan the frames of each answer span, not
  only the marker images, for node names, internal addresses and IPs. The writer's own reviews of terminal takes
  (command output, complete in the transcript) are not affected; for a chat take the transcript does not exist.
- A sampled review is not a review of every frame. Each section states N.
- The write guard sees HTTP requests only. The OpenClaw Control UI works over a WebSocket, which it does not see, so an empty `writes` list proves nothing for `openclaw` (as relayed by the coder, 2026-11-17).
- Most published GIFs had no take-time write guard (survey in the afternoon evidence; the shared guard of `6df63b54` covers only the converted walkthroughs, and the published ones are not converted). Their created objects were deleted and counted; other writes of their pages were not blocked or listed.
- Nothing here was recorded before the sprint's code reached `devel`.
